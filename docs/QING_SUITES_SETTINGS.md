# 两个合并插件的设置与升级

## 后台设置入口

AstrBot 网页端打开 **插件**，找到 **对话管理** 或 **图片与主题**，点击配置齿轮。两者使用 AstrBot 原生可视化设置页，无须额外前端、容器或端口；配置由各自的 `_conf_schema.json` 声明。每个顶层分组都有独立的「启用此功能模块」开关。

保存后按后台提示重载对应插件，确保 HTTP 会话、表情池、限流器与包装都按新设置重建。停用整个插件会撤销本插件的运行时包装、后台任务和 HTTP 会话；独立模块可通过配置开关关闭后重载。

### 对话管理

| 分组 | 可调整内容 |
| --- | --- |
| @ 唤醒 | 启用开关；继续复用 AstrBot 原生对话流程，不改 /aa 前缀配置 |
| 随机表情回应 | 随机模式、候选 QQ 表情列表、固定回退表情；只在真实 LLM 请求阶段回应，附加接口最多等待 1 秒 |
| 搜索、历史与响应管理 | 搜索最多返回条数（默认 10，Tavily 最多 20）；历史搜索自动清理；旧工具结果白名单、保留条数与字符上限；普通聊天 180 秒、工具任务 600 秒；同群独立排队；闲置新对话开关和小时数（默认 8） |
| 上下文图片预算 | 当前模型上下文的图片总传输量上限，默认 10 MB，可设小数；保留文字和群聊轮数 |
| 记忆兼容修复 | LivingMemory 兼容修复开关；保留上游过滤、访问权限及版本校验 |
| 随机选择 | /roll 功能开关；选项和数字区间的原指令保持 |
| QQ 群抽奖 | 各场编号、报名、开奖和提醒。按群绑定腾讯文档，并设置 AstrBot MCP 服务名。 |

响应预算从实际 Agent 执行开始计时，同群排队时间不计入；明确生图沿用生图模块自己的执行预算。闲置周期继续以成功发送消息的观察记录为准，迁移不重置原计时。

### 群抽奖

| 指令 | 用途 |
| --- | --- |
| `/抽奖`、`/抽奖 进行中 [页码]` | 查看本群正在报名的抽奖 |
| `/抽奖 帮助` | 发一张发起、报名和开奖流程图 |
| `/抽奖 帮助 文字` | 查看完整的文字帮助 |
| `/抽奖 发起` | 打开手机表单，填完奖品、人数和截止时间，再将确认指令发回原群 |
| `/抽奖 发起 2 2026-12-01 21:00 Steam 礼物` | 创建独立编号的抽奖，按北京时间截止，抽 2 人 |
| `/抽奖 报名` | 只有一场可报名时直接加入。多场时按提示在 2 分钟内单独发送对应的数字 |
| `/抽奖 列表`、`/抽奖 报名 12` | 查看本群待办抽奖，或报名第 12 场并取得固定序号 |
| `/抽奖 名单 12` | 查看第 12 场报名序号和昵称 |
| `/抽奖 开奖` | 发起人给自己的待开奖场次开奖。能开奖的场次有多个时，按提示指定编号 |
| `/抽奖 确认` | 收到提前开奖询问后，原群同一 QQ 号在两分钟内确认，按届时报名名单开奖 |
| `/抽奖 开奖 12`、`/抽奖 取消 12` | 由该场发起人、群主或群管理员处理 |
| `/抽奖 结果 12`、`/抽奖 历史` | 查看原开奖结果和已结束记录，支持页码 |
| `/抽奖 总结` | 发送本群抽奖统计图，含参与次数榜和中奖次数榜 |
| `/抽奖 总结 文字` | 查看本群统计和榜单前三位的文字版 |
| `/抽奖 同步状态` | 查看腾讯文档同步状态 |
| `/抽奖管理`、`/抽奖 管理` | 领取本群的限时网页管理入口 |
| `/抽奖 访问 …` | 群内备用入口由领取者用页面生成的指令确认 |

也可在群里真实 @ 机器人后输入动作，例如 `@机器人 报名 12`。多场报名的数字只接受收到选择提示的同一 QQ 号在原群发送的纯文本，直接发数字即可。每个 QQ 号在每场只报名一次。到点停止报名，发起人收到 @ 提醒后手动开奖。发起离截止超过一小时的活动另有一次提前提醒。抽奖按固定报名序号随机抽取且不会重复抽到同一人，报名人数不够时按实际人数开奖。首次公布结果会 @ 开奖人和中奖人，重复开奖指令返回原结果。

手机表单和网页管理台在「对话管理 → QQ 群抽奖」填写独立 HTTPS 域名后开启。将该域名反代到 AstrBot 容器的 HTTP 端口 `8769`，与 AstrBot 管理后台分开。反代需要放行 `/`、`/a/*`、`/f/*`、`/logout`、`/panel`、`/panel/*`、`/assets/raffle.css` 和 `/assets/raffle.js`，并保留浏览器的 Origin 请求头。请关闭访问日志或对一次性链接路径脱敏。

- 在目标群发 `/抽奖管理`，机器人优先将一次性入口私发给领取者。私聊无回执时，群内的备用入口须由同一个 QQ 号在原群确认。链接 5 分钟内可用一次，打开的浏览器会话有效 30 分钟。请勿转发私发链接。网页每次操作都会重新核对群成员及管理权限。
- 群友可以在网页准备、发布、报名并查看结果，也可继续用 QQ 指令。表单默认抽 1 人、2 小时后截止，草稿保留 15 分钟。同一份草稿只会发布一次。
- 每群的管理台支持按状态、奖品、编号、个人发起或参与筛选。发起人和群管理可开奖、取消、查看报名号和昵称、提醒回执及操作流水，并导出 CSV。
- QQ 与网页共享报名名单和固定序号。QQ 群内可二次确认提前开奖，重复操作返回原结果。发布时发一条普通群消息，写明发起人、奖品与截止时间。网页发布、开奖和取消会排队向原群发消息。QQ 离线时等待恢复，发送结果不明确时在流水显示状态，避免重复发送。

云同步复用 AstrBot 的 MCP 服务。使用有表格编辑权限的账号获取 Token，在 AstrBot 的 MCP 管理中新建并启用 `tencent-docs-sheet`，类型 `streamable_http`，地址 `https://docs.qq.com/api/v6/sheet/mcp`，请求头 `Authorization` 填 Token 原值。可单独关闭模型工具，插件直接调用这条连接。 [腾讯文档授权](https://docs.qq.com/open/auth/mcp.html)

在「对话管理 → QQ 群抽奖 → QQ 群与腾讯文档绑定」里，每项填 `群号=腾讯文档在线表格链接`。每个群用自己的文档。插件在目标文档创建并只写入 `bot 抽奖记录` 标签页。打开「仅允许已绑定腾讯文档的群发起抽奖」后，QQ 和网页都要求群已绑定才可发起。升级自 v1.1.0 时，请在新列表里明确填入原文档对应的群号。授权暂未通过时同步会后台重试，批准编辑权限后自动补录。

本地 SQLite 保存完整抽奖流水，网页可查看。腾讯文档每场抽奖占一行，按顺序写入发起人、内容、获奖人、截止时间，以及从「参与通道」列向右排列的参与昵称。获奖人在开奖后填入同一行。机器人按原始行列更新，建议使用筛选查看。云端暂不可用时，本地抽奖照常处理，恢复后继续同步。

网页的「抽奖总结」合并本群机器人记录和已导入的腾讯文档历史快照，支持按来源查看场次。参与和中奖按人次累计。历史表格里没有填中奖人的场次显示「未登记结果」。历史快照独立保存在 SQLite 中，导入过程只读云文档。

QQ 总结图和网页均显示参与榜及中奖榜前 10 位，同次数并列。排行中每人每场最多各记一次。机器人记录按 QQ 账号统计，历史记录按登记昵称统计。历史昵称只在唯一匹配到机器人记录中的同名账号时合并。

抽奖后台的前端位于 `frontend/raffle-dashboard`，使用 [BoardUI](https://www.boardui.com/components) 的 MIT 基础组件。修改后在仓库根目录执行 `npm --prefix frontend/raffle-dashboard ci`、`npm --prefix frontend/raffle-dashboard run check` 和 `npm --prefix frontend/raffle-dashboard run build`，将构建后的静态资产与插件一并打包。AstrBot 直接提供这些资产。

### 图片与主题

| 分组 | 可调整内容 |
| --- | --- |
| 生图与 GIF | 服务地址、接口路径、密钥、模型、尺寸、质量、格式、背景、张数、超时、代理、单图大小和并发；进度提示、明确生图请求的工具调用保障及提示开关 |
| 文转图与主题 | 默认主题 ID、名称、副标题、头像、头像/页脚显示、服务能力探测回退地址；Git 同步开关、仓库、分支、目录、启动同步及更新间隔 |
| 图片来源搜索 | 触发词、引用图回退、搜索引擎与密钥、阈值、结果数量、超时/并发/冷却、贴表情、缓存、网络、安全及输出设置 |

上下文图片预算 10 MB 与生图单图下载限制 20 MB 是两个不同用途的设置。GIF 能力取决于生图服务实际返回；工具仍报告实际格式。主题服务继续是独立 Docker，插件不将主题或图片数据塞进 LLM 上下文。

现有指令与工具名不变：`/aa`、真实 @、`/i`、`/imagegen`、`/生图`、`/i --gif`、`/t2i`、`/图样式`、`/roll`、`/memory_fix_status`、搜图关键词与管理指令，以及 `astrbot_generate_image`。主题管理仍仅 AstrBot 管理员可用，人格工具白名单仍有效。

## 从旧单插件升级

这是一次文件布局和插件标识调整。建议先备份，并在没有执行中任务时切换。不要直接使用仓库根地址安装；从 Releases 下载两个 ZIP，经后台本地上传安装。

1. 备份旧插件代码、对应配置、插件专属状态、启用清单和自定义指令设置。保留 LivingMemory、群分析本体及数据，不删除数据库。
2. 在 AstrBot 本地运行仓库 `scripts/migrate_qing_suites.py`，先预览、再显式 `--apply`。传入实际数据目录和从后台盘点得到的旧启用插件名 JSON 数组。脚本只在本地读取配置，支持 UTF-8 BOM，已有新设置优先；成功导入后写独立标记，重复执行不会用旧值覆盖新值。密钥不输出到预览、日志或 Git。
3. 默认配置文件自动检查；若有额外 AstrBot 配置档，使用 `--profile-json` 显式传入实际文件。显式插件白名单会添加对应新插件，并保留旧名字作为功能级选择掩码；`["*"]` 与空列表保持不变。原会话启停记录继续按旧模块名字查询，新插件总开关优先。
4. **先停用 9 个旧插件，再上传两个新包。** 套件发现旧插件仍在启用时保持休眠，避免同时注册相同指令/生图工具或重复包装；停用旧插件后需要重载新套件。
5. 验证后台两个设置页、模块加载日志、/aa 与 @、图片发送、主题状态及预算。确认后把旧源码安装目录移出 `data/plugins` 保存为备份；可在空闲窗口重启 AstrBot 清理旧注册信息，保留 QQ 登录容器。

当前导入覆盖：mention_llm、get_emoji_reply、tavily_result_limiter、context_image_limiter、memory_recall_fix、roll、imagegen、t2i_style、qing_image_source。旧 model_footer 继续停用；link_resolver 的原停用状态保留。

兼容期继续使用 `plugin_data/astrbot_plugin_t2i_style/` 的会话主题与 Git 缓存、`plugin_data/astrbot_plugin_qing_image_source/` 的搜图缓存，以及旧上下文插件的 KV 命名空间。这些目录与 KV 现在也服务于新插件，**不要因为旧代码已归档就删除它们，或用旧插件的“卸载并删除数据”按钮清理**。导入标记位于新套件自己的 plugin_data 目录。

如有自定义指令重命名或禁用记录，切换前按旧/新 handler 对照迁移；不要让 AstrBot 在卸载旧 handler 时丢失这些记录。本次目标 NAS 未发现旧自用插件的自定义指令记录。

## 回退与测试

先停用新套件、撤销包装，再恢复旧源码并按原清单启用。不要让新旧功能同时运行，不覆盖全局模型配置、人格或第三方记忆数据库。配置迁移不会删除旧设置或旧状态。

测试使用真实 AstrBot 4.29.4 接口、模拟模型/平台/存储以及 loopback HTTP。执行时设置 `ASTRBOT_ROOT` 到独立测试目录，避免碰到真实数据；安装包排除 `tests/`。生图服务调用和 QQ 群发送的线上验收必须单独授权，普通测试不会发消息或调用付费模型。

在已安装 AstrBot 4.29.4 及测试依赖的 Python 环境中执行 `python scripts/test_qing_suites.py`，脚本自动设置独立数据根并分两轮测试。记忆回归测试需要 LivingMemory 2.7.0-beta.2 源码；默认使用目标 Docker 的安装目录，其他位置通过 `LIVINGMEMORY_SOURCE` 显式指定。仓库直接运行 pytest 默认仅收集新套件的原生入口/迁移测试，不收集保留的历史单插件测试。

对话管理包按 AGPL-3.0 发布并附记忆兼容代码来源；图片与主题包保留搜图模块 MIT 许可和各作者署名。群分析和 LivingMemory 仍走各自的上游更新。
